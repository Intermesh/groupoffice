# Review of the `community/marketplace` client — 2026-09-21

The first review of this module (5,968 lines of PHP + 2,854 of JS). `marketplaceserver`
had been through two rounds of review by then; the client had been through none, even
though it is the half that downloads and unpacks PHP from a remote server — the riskier
side of the pair.

This file holds the **result**, not the review itself: what was verified against the code,
what was fixed, and above all what was checked and found sound, so the next round does not
look for it again.

## Verified as sound — do not reopen

- **XSS from server-supplied strings.** `GO.errorDialog.show(error)` HTML-encodes
  (`ErrorDialog.js:72` — `nl2br(htmlEncode(error))`, the `html` parameter defaults to
  `false`), the catalogue templates use `{title:htmlEncode}` / `{description:htmlEncode}` /
  `{logoUrl:htmlEncode}`, and the path through `go.Notifier.flyout` (which injects
  `description` via innerHTML) encodes the module name itself. `logoUrl` only ever reaches
  an `<img src>`, where `javascript:` does not execute.
- **The order of steps in a download** (`controller/Repository.php::download`): the
  signature is fetched BEFORE the download and pins the concrete version, it is verified
  against the **pinned** key before anything is extracted, and only then are the entry
  names validated and the archive unpacked. The temp directory lives inside the target
  package dir (same filesystem, so the final `rename()` is not a copy) and is dot-prefixed
  (ClassFinder skips dot-directories). There is a backup and a restore on a failed swap,
  including an error naming the surviving backup.
- **Gating.** `download()` and `refresh()` require `hasPermissionLevel(LEVEL_MANAGE)`,
  which for this entity means admin. `validate()`, `register()`, `login()` and
  `resendVerification()` carry `assertAdmin()` at the API boundary (they have no entity to
  hang a check on) — without it `validate()` would be an SSRF primitive.
- **`LicenseVerifier`**: the JWT leeway is widened for that one decode and restored
  afterwards; `exp` is then re-checked strictly, so the leeway can never extend a license.
  An empty `hostname` claim fails closed. A wildcard requires a dot-anchored suffix.

## Found and fixed

| # | Where | What |
|---|---|---|
| 1 | `model/Repository.php` | The public `getPermissionLevel()` overridden instead of `internalGetPermissionLevel()`, so `Entity::EVENT_PERMISSION_LEVEL` never fires. The same finding as #6 on the server. |
| 2 | `model/Repository.php` | That overridden level had no matching `applyAclToQuery()`. For a `jmap\Entity` the base implementation is a no-op, so `MarketplaceRepository/query` returned ids (and `name`/`url`) even to a user without `mayManage` on the module. The token, signing key and JWT never leaked — they are `protected` with no getter. |
| 3 | `views/extjs3/SystemSettingsPanel.js`, `RepositorySection.js` | `permissionLevel` was loaded into the store and passed into the section, and then **nobody used it**. A user with `mayManage` (not an admin) may open the System Settings tab (`systemsettings/Panel.js:5` lets `mayManage` through) and saw Add repository / Update all / Edit / Delete / Refresh licenses / Download — every one of which the server answers with a 403. Those actions are now hidden. |
| 4 | `controller/Repository.php::refresh` | The return value of `$repo->save()` after `flagKeyMismatch()` was discarded, so the flag might not survive while the user still saw the error. Same class as #7 on the server. |
| 5 | `controller/Repository.php::download` | The lock file `.marketplace_<module>.lock` was created in the package dir and never removed; and on a failed `flock()` the handle leaked (the throw is before the `try`). |
| 6 | `lib/PackageValidator.php` + `download()` | An archive whose only entry is a **file** named exactly `{module}` passes (`$normalized !== $module` is the escape branch), and `rename()` then puts a file where the module directory belongs. An `is_dir()` check was added before the swap. |
| 7 | `lib/LicenseVerifier.php` | `unexpired()` compared `expiresAt` loosely while `tokenUnexpired()` uses `is_int()`. In PHP 8 a non-numeric string would compare as "greater" and license forever. Only reachable by a holder of the server's private key, so this is defence in depth. |
| 8 | `lib/LicenseHost.php` | `normalize()` skipped port stripping for a bracketed IPv6 literal, so `[::1]:8080` kept its port. |
| 9 | `lib/PackageValidator.php` | The module name was validated with `/i`, while the server and `download()` both insist on lowercase. Dead tolerance that hid the mismatch. |
| 10 | `RepositoryDialog.js` (2x), `LoginWindow.js` | An error dialog whose entire body was a **field label** ("Repository URL", "E-mail") instead of a sentence. |
| 11 | `language/*.php` (32 files) | The `mayManage` key was missing everywhere, so the Permissions dialog showed the bare right name. The server has it (`"mayManage" => "Manage marketplace"`). |
| 12 | `CatalogGrid.js` | `emptyText` without `deferEmptyText: false` — the documented GO trap where a fast reply means the text never appears. |

## Found by the e2e run, not by reading

| # | Where | What |
|---|---|---|
| 13 | `marketplaceserver/Module.php::pageRegister` docblock, `marketplace/controller/Repository.php::register` | The server's docblock claimed `/register` "returns an API token so the client can start immediately". It does not — and that is correct: issuing a token only on the "new account" path would reveal that the account did not exist yet. The client read `'token' => $result['token'] ?? null` from the response, which was always `null` (a dead field). `RegisterWindow.js` describes the real behaviour correctly. Both are now aligned with the code. |

## What the e2e proved, so nobody has to check it by hand

The `tests/e2e/` harness (two instances, 33 checks, `ALL GREEN`) — details in its README:

- registration -> e-mail verification -> login -> token -> saving the repository (pinning
  package, name and key) -> catalogue -> download -> license, all across a real network hop;
- a download without an entitlement is refused **with the server's own message** and
  nothing is written to `go/modules`;
- a revoked entitlement reaches the client on the next refresh and the offline gate stops
  licensing the module;
- the pinned signing key holds: a server that regenerated its key pair is refused and the
  repository is flagged, never silently re-pinned.

**A trap worth knowing about**, hit while writing it: the scenario has to clear its own
leftovers on BOTH sides. A verified customer left over from an earlier run made the check
"an unverified account cannot sign in" fail and look like a product bug. It is not —
`Authenticator::login()` checks the account state correctly (`lib/Authenticator.php:77`).
`scenario.py` therefore starts by cleaning up.
